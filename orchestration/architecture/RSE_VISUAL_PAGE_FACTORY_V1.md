## Purpose

Turn canonical book text into visually strong RSE pages without making each page a new manual design project.

Pipeline:

`CANONICAL TEXT → PAGE IMPACT → PAGE FAMILY → SCENE SPEC → ASSET SLOTS → LOCKED TEMPLATE → RENDER → QA → SMALL REVIEW PACKET`

The Scene Compiler may choose among approved families/variants. It may not invent freeform page geometry in production.

## Scene Spec

A scene spec is structured data between source and renderer.

Minimum fields:

```json
{
  "page_id": "hmda.en.front.04",
  "page_family": "orientation_menu",
  "template_id": "hmda.orientation.v1",
  "visual_intensity": "medium",
  "blocks": [],
  "asset_slots": [],
  "interaction_or_write_space": [],
  "source_refs": [],
  "content_sha256": "...",
  "scene_spec_sha256": "..."
}
```

Block kinds:
- title
- subtitle
- narrative
- section_bar
- stat
- evidence_tile
- dossier
- comms_message
- quote
- instruction
- numbered_step
- badge
- response_field
- writing_zone
- index_row
- visual_anchor

Asset-slot kinds:
- locked_character_portrait
- locked_logo
- icon_svg
- prop_sprite
- spot_illustration
- hero_illustration
- decorative_texture
- code_generated_ui

## Visual added-value policy

Use visuals only when they improve:
- comprehension;
- story immersion;
- brand identity;
- hierarchy;
- interaction;
- emotional pacing.

Do not decorate legal/publishing copy just to fill space.
Do not sacrifice writing room or readability for atmosphere.

## Page-family production rules

### title_evidence_grid
- no generic centered cover-page look;
- evidence/Room Zero identity is structural;
- title remains code-rendered;
- hero/decorative art may be image asset;
- no AI-generated final typography.

### publication_record
- legal text is dominant;
- visual branding is subtle;
- no busy graphic-novel composition behind rights text.

### cinematic_invitation
- one dominant story object/scene;
- strong black/white silhouette;
- source text overlay by code;
- 0 mark is exact asset/code, never invented variant.

### character_dossier_trio
- exact approved portrait IDs only;
- same template across both squad pages;
- role/strength/habit are structured fields;
- no AI text baked into portrait art.

### interactive_credential / workspace_sheet
- writing lines/zones generated by code;
- generous pencil space;
- illustration cannot occupy response regions.

### rules_reference
- diagrams/legend are code-generated;
- decorative art may not resemble semantic map symbols.

### case_index
- stable rows/numbering;
- code owns titles and ordering;
- visual treatment may use file tabs/scanner rails.

### act_breaker
- highest freedom for decorative illustration because there is minimal structured content;
- still uses locked identity/style tokens.

## Template lifecycle

`DRAFT → GOLDEN_CANDIDATE → OWNER_APPROVED → FROZEN_TEMPLATE`

After a template family is frozen:
- new pages may only populate slots;
- scene compiler may choose approved variants;
- Codex may not create a new layout because text is longer;
- overflow policy is standard → compact → split → exception gate.

## Scene Compiler responsibilities

The Visual Scene Compiler:
1. reads canonical page content;
2. selects an existing page family;
3. maps every source span to one block;
4. assigns semantic emphasis;
5. declares required asset slots;
6. outputs schema-valid scene JSON;
7. never rewrites canonical copy unless a separate editorial task authorizes it.

If no approved family fits:
`NEW_TEMPLATE_REQUIRED`.

It does not silently improvise.

## Art system

Art is generated independently from page rendering.

`ASSET SLOT → PROMPT COMPILE → IMAGE GENERATION/EDIT → QA → CONTACT SHEET → APPROVAL/AUTO-RULE → FROZEN_ASSET`

Atomic only:
- portraits;
- props;
- spot art;
- hero art;
- textures.

Never:
- full final text page;
- map with semantic walls/doors;
- final tables;
- coordinate grid;
- witness board with canonical text.

## Automatic QA

Per changed page:
- schema validation;
- source-span completeness;
- no duplicate/missing copy;
- overflow;
- min font;
- safe zone;
- asset SHA;
- character identity;
- logo identity;
- grayscale/color contract;
- write-space minimum;
- template hash;
- screenshot repeatability;
- visual diff against family thresholds.

A vision/reviewer agent may flag aesthetic anomalies, but code gates structural correctness.

## Review packet

Owner sees only:
- new template candidate pages;
- changed pages caused by source update;
- new asset candidates;
- automated QA flags.

For a normal text update, packet should be a handful of pages, not the full book.
