## Artifact minimum

- source bytes/hash/revision, version inventory and authority reason;
- stable content IDs with source locators and complete coverage;
- wording-free function brief for localize; diagnostic issue ledger for upgrade;
- immutable facts, names, mechanics, answers, consent, claims and dependencies;
- GOLDEN_KEEP registry and protected segments;
- function/repetition map covering pacing, activity mechanics and emotional load;
- allowed changed IDs, base hash, actual changed IDs, dependency closure;
- target candidate, clean manuscript, backcheck and review findings;
- exact candidate hash, unresolved items and honest test/CI state.

For multiple versions compare by segment function. Preserve the best accepted
version; do not reintroduce a known defect from a newer file. Isolate contradictory
source truth and continue independent work.

## Wording-free brief

For each segment record function, reader action/understanding, facts, chronology,
mechanics, emotional job, comic mechanism, speaker/voice, consent/claim boundaries,
dependencies and relevant format constraints. Do not put source sentences or literal
translations into free-text brief fields. The first writer receives the brief and
exact necessary proper nouns/tokens only, plus target voice/audience. Backcheck
later sees original + final target + invariants.

CLI guards keys/structure, not semantics of wording-free summaries. Inspect briefs
for sentence leakage/completeness before handoff. Metadata is not proof a writer
never saw the source. Use a fresh agent with no inherited conversation for this
writer when the environment permits.

## Independent reviews

Use native-language/idiom + book register, meaning/mechanics/claims, audience/family
ear/consent, and logic/continuity/repetition reviews. Add brand, humor or culture
only where useful. Reuse current RSE PL specialists; provide equivalent EN briefs
without pretending an English specialist file exists. Reviews first diagnose;
one writer integrates targeted changes.

Each receipt names reviewer, actual stage, exact candidate SHA-256, scope and
findings. Code verifies binding; it cannot prove a review happened or prose is
good. Never generate PASS receipts merely to make a check green.

Meaning: check every source function, facts, numbers, negation, modality, clues,
hints/answers, safety, consent, promises. Native: idiom, collocation, word order,
rhythm and written register. Audience: reject embarrassment, forced vulnerability,
gratitude/apology, jargon and jokes at a participant's expense. Logic: references,
chronology, pacing and functional repetition as well as repeated words.

Resolve disagreement by current owner lock → truth/safety/mechanics → project/voice
profile → GOLDEN_KEEP → demonstrated reader defect → stylistic preference.

## Scope and release

Same-language editing is conservative: record a defect before replacing a strong
line. Cross-language authoring frees wording, never truth. Frozen content requires
segment-specific unlock before later edits. A generic request to improve a project
does not unlock frozen segments.

Full acceptance belongs to the owner. Render/layout/image agents consume frozen
text; they cannot silently tighten it. Try an approved layout variant, then harmless
approved tightening, then an approved split, then an exception. Surface-fit proof
must bind the candidate's exact source hash.

No text check establishes KDP preflight, surface fit, physical proof or release.
Missing assets/render/device evidence cannot be converted into text PASS.
