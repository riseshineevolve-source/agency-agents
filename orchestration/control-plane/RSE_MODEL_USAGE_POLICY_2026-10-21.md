## What actually saves allowance

- Hashing, assembly, rendering, validation and status collection use deterministic
  scripts first. A model supervises exceptions rather than narrating every step.
- Read relevant checkpoint/diff/source sections. Do not reload whole books,
  unrelated mailboxes or complete agent catalogs on each turn.
- Change and review only affected pages/screens; reuse approved art and templates.
- Avoid duplicate full-context workers and repeated status polling. Delegation
  requires the applicable user/instruction authorization and a distinct purpose.
- Keep final language, art and security judgment at an adequate capability level.
  Luna does not independently approve a premium manuscript or waive a release gate.
- For an unchanged failure, inspect evidence before another attempt; two attempts
  on the same hypothesis is the limit before changing the approach. Missing files,
  offline tools or failed runner startup are not solved by a stronger model.
- If real usage is unavailable, record UNKNOWN. No invented weekly percentage,
  reset time, per-chat quota or guaranteed savings multiplier.

Image generation still uses its own image tool/model and allowance. Changing the
chat controller does not change the image model or make repeated generations cheap.
Preserve approved originals and use targeted edits when authorized.

## Communication and application

Every registered lane and supplemental desk reads this policy at startup and the
next meaningful checkpoint. Central publishes the notice in its own mailbox and
the registry/autonomy/bootstrap entrypoints. Other lane mailboxes stay lane-owned.

At its next checkpoint each writer records policy acknowledgment plus the
**observed** runtime model/reasoning/speed in its own mailbox or checkpoint.
If a setting cannot be observed, say UNKNOWN. Use `RECOMMENDATION_ONLY` when the
runtime cannot be changed; only report `APPLIED_AND_OBSERVED` after verification.
No need to ask the owner again for this authorized routing policy.

Repository files do not switch open Work chats or the current root model. Work
selection uses the client's model/reasoning controls when available. Codex can
start a task with an explicit model, e.g. `codex exec -m gpt-6-luna "<bounded task>"`
or `codex exec -m gpt-6.1-sol "<implementation task>"`; choose reasoning/speed in
the supported client settings. No live Codex launcher was changed in this run.

Publishing the notice is not acknowledgment or a mechanism to wake closed chats.
Existing writers, privacy boundaries, approved source and release gates remain.
